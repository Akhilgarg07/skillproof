answer
I fixed the bug in `median()`, and all 3 tests now pass.

**The bug:** `median()` always returned the single middle element. That's only correct for an odd number of values. With an even number there are two middle values, so it was returning the upper one. For example, `[1, 2, 3, 4]` gave `3` instead of `2.5`.

**The fix** in `stats.py`: when the list has an even length, it now returns the average of the two middle values:

```python
def median(values):
    ordered = sorted(values)
    middle = len(ordered) // 2
    if len(ordered) % 2 == 0:
        return (ordered[middle - 1] + ordered[middle]) / 2
    return ordered[middle]
```

pytest isn't installed here, so I ran the tests with `python -m unittest`.

One thing I left alone: `mean()` and `median()` still crash on an empty list. The tests don't cover that case.

```python
def mode(values):
    """Return the most common value; ties are broken by the smallest value."""
    counts = {}
    for value in values:
        counts[value] = counts.get(value, 0) + 1
    return min(counts, key=lambda v: (-counts[v], v))
```

**`test_stats.py`:** I added `mode` to the import and two tests:

An empty list will raise a `ValueError`, the same way `mean` errors on an empty list.
